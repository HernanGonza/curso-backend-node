Proyecto Final: Arquitectura y Setup desde Cero

Arrancamos el proyecto final del curso: una API de productos construida completamente desde cero. En esta clase se define el modelo de datos, la arquitectura en capas, y se deja todo el proyecto inicializado, configurado y con su base de datos lista.

60 minutos Requiere Bloque 6 completo
Objetivos de la clase
  • Comprender el alcance completo del Proyecto Final: una API de productos construida de punta a punta.
  • Diseñar el modelo de datos con dos tablas relacionadas: productos y categoria_producto.
  • Definir por escrito todos los endpoints de la API antes de programar.
  • Armar la estructura de carpetas del proyecto siguiendo una arquitectura en capas.
  • Inicializar el proyecto de Node.js desde cero con npm.
  • Instalar y comprender cada una de las dependencias necesarias.
  • Configurar correctamente las variables de entorno y el control de versiones.
  • Crear las tablas en PostgreSQL usando Antares y cargar datos de prueba.

01¿Qué es el Proyecto Final?

A partir de esta clase arrancamos el Proyecto Final del curso: una API REST de productos, construida completamente desde cero a lo largo de cuatro clases. No vamos a reutilizar ningún archivo de ejercicios anteriores — el proyecto empieza literalmente en una carpeta vacía y termina publicado en internet en la Clase 32.

El recurso principal de la API es productos. Para mantenerlo simple pero funcional, cada producto va a tener solo tres datos propios: su nombre, su precio y la categoría a la que pertenece.

💡
Por qué empezar de cero: Arrancar un proyecto real desde una carpeta vacía es distinto a completar ejercicios sueltos. Acá se practica también el orden de las decisiones: primero se piensa el modelo de datos y los endpoints, después se arma la carpeta, y recién ahí se escribe la primera línea de código.

02Arquitectura en Capas

El proyecto se organiza en capas, cada una con una única responsabilidad.

CapaResponsabilidad
routesDefine qué URL y qué método HTTP dispara cada función.
controllersRecibe el request, llama a la capa service, y decide qué responde al cliente.
servicesContiene las queries SQL reales contra PostgreSQL.
middlewaresFunciones que se ejecutan antes del controller: validaciones y manejo de errores.
🛡️
Por qué separar en capas: Si cambia la forma de guardar los datos, solo se modifica services/. Si cambia una validación, solo se toca middlewares/. Cada capa se puede editar sin romper a las demás.

03Diseñando el Modelo de Datos

El proyecto usa dos tablas relacionadas. categoria_producto es una tabla simple de referencia, y productos es la tabla principal, con una clave foránea hacia la primera.

sql
CREATE TABLE categoria_producto (
  id SERIAL PRIMARY KEY,
  nombre VARCHAR(50) NOT NULL
);

CREATE TABLE productos (
  id SERIAL PRIMARY KEY,
  nombre VARCHAR(100) NOT NULL,
  precio NUMERIC(10,2) NOT NULL,
  categoria_producto_id INTEGER NOT NULL REFERENCES categoria_producto(id)
);

Cada producto tiene exactamente tres propiedades propias: nombre, precio y categoria_producto_id (además del id autogenerado).

🛡️
Por qué agregar la tabla de categorías: categoria_producto no tiene su propio CRUD en esta API: solo se carga con un par de filas de prueba. Su único propósito es habilitar un JOIN real cuando se consulten productos.

04Definiendo los Endpoints de la API

MétodoEndpointDescripción
GET/productosLista todos los productos, incluyendo el nombre de su categoría.
GET/productos/:idDevuelve un producto puntual por su id.
POST/productosCrea un producto nuevo.
PUT/productos/:idActualiza un producto existente.
DELETE/productos/:idElimina un producto existente.

06Inicializando el Proyecto con npm

bash
# Crear la carpeta del proyecto y entrar en ella
mkdir proyecto-final-api
cd proyecto-final-api

# Inicializar el proyecto de Node.js
npm init -y

Así queda el package.json generado automáticamente — resultado real de npm init -y, sin editar nada todavía:

json
{
  "name": "proyecto-final-api",
  "version": "1.0.0",
  "description": "",
  "main": "index.js",
  "scripts": {
    "test": "echo \"Error: no test specified\" && exit 1"
  },
  "keywords": [],
  "author": "",
  "license": "ISC"
}
⚠️
Esto es lo que npm genera por defecto: No tiene todavía express, pg, dotenv ni un script start. Todo eso se agrega en los próximos pasos.

07Instalando las Dependencias

bash
# Dependencias de produccion
npm install express pg dotenv

# Dependencia de desarrollo
npm install --save-dev nodemon
PaquetePara qué se usa
expressEl framework sobre el que se construye el servidor.
pgEl driver para conectarse a PostgreSQL.
dotenvCarga las credenciales desde .env.
nodemonReinicia el servidor automáticamente en desarrollo.

Los scripts start y dev hay que escribirlos a mano:

json
{
  "name": "proyecto-final-api",
  "version": "1.0.0",
  "main": "index.js",
  "scripts": {
    "start": "node index.js",
    "dev": "nodemon index.js"
  },
  "dependencies": {
    "express": "^4.19.2",
    "pg": "^8.11.5",
    "dotenv": "^16.4.5"
  },
  "devDependencies": {
    "nodemon": "^3.1.0"
  }
}

09Creando las Tablas en Antares

Con las credenciales del .env ya definidas, se abre Antares, se conecta a la base proyecto_final, y se ejecuta el script completo:

sql

  id SERIAL PRIMARY KEY,
  nombre VARCHAR(50) NOT NULL
);

CREATE TABLE productos (
  id SERIAL PRIMARY KEY,
  nombre VARCHAR(100) NOT NULL,
  precio NUMERIC(10,2) NOT NULL,
  categoria_producto_id INTEGER NOT NULL REFERENCES categoria_producto(id)
);

INSERT INTO categoria_producto (nombre) VALUES
  ('Perifericos'),
  ('Accesorios');

Por qué Antares y no la terminal: Permite ejecutar el script completo de una vez y ver el resultado en una grilla.
