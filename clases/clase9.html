Funciones en JavaScript

Domina el pilar central de la lógica backend: la declaración y expresión de funciones, el manejo preciso de parámetros y valores de retorno, el control de alcances (scope), patrones avanzados de validación y la arquitectura basada en callbacks.

60 minutos Requires Clase 8
Objetivos de la clase
  • Entender qué es una función y por qué son fundamentales en programación.
  • Declarar funciones utilizando declaración estándar (function declaration) y de expresión (function expression).
  • Diferenciar y dominar de forma exacta conceptos de parámetros, argumentos y valores de retorno.
  • Conocer en profundidad el Scope (alcance) léxico de las variables.
  • Aplicar el patrón de retorno temprano (early return) para optimizar validaciones limpias en backend.
  • Escribir funciones modulares, semánticas y completamente reutilizables orientadas a lógica de servidores.

01¿Qué es una Función?

Una función es un bloque de código que agrupa instrucciones bajo un nombre descriptivo. En lugar de repetir la misma lógica de programación varias veces a lo largo de un archivo, se escribe una sola vez dentro de una función y se la "invoca" o "llama" exactamente cuando se la necesita.

💡
Lógica de Backend: En el desarrollo del lado del servidor, casi todo el procesamiento se compone de funciones: validar la estructura de un email, calcular los descuentos de un carrito, procesar pasarelas de pago cifradas o buscar registros dentro de una base de datos.

Analogía práctica: Una función se asemeja a una receta de cocina bien definida. La receta tiene un nombre único ('Arroz con leche'), recibe ciertos ingredientes (que actúan como parámetros) y produce un resultado final comestible (el valor de retorno). No importa cuántas veces ejecutes la receta: el orden lógico de los pasos internos siempre permanece constante.

02Declarar y Llamar Funciones

En JavaScript existen dos formas principales y nativas de estructurar una función en tu código fuente:

Forma 1: Declaración de función (Function Declaration)

Es la sintaxis tradicional. Utiliza la palabra clave reservada, un nombre explícito, parámetros entre paréntesis y la apertura del bloque de ejecución.

javascript
function saludar() {
  console.log('Hola!');
}

Para ejecutar las líneas dentro de la función, debemos realizar la llamada invocándola por su nombre seguido de paréntesis:

javascript
saludar(); // Llama la función - ejecuta el código adentro
saludar(); // Se puede llamar cuantas veces se quiera en el programa

Forma 2: Expresión de función (Function Expression)

Consiste en definir una función anónima y asignarla directamente como valor dentro de una variable constante.

javascript
const saludarExpression = function() {
  console.log('Hola desde expresión!');
}; // Lleva punto y coma final porque técnicamente es una asignación de variable

saludarExpression(); // Se invoca exactamente igual utilizando el nombre de la constante

Diferencia clave en ejecución: Hoisting

Tipo de Definición Comportamiento en Motor de Ejecución (Hoisting)
Function Declaration Se puede utilizar e invocar líneas antes de su declaración física en el archivo. JavaScript las "eleva" al inicio de forma automática al compilar.
Function Expression No se puede invocar bajo ningún motivo antes de la línea exacta donde fue declarada, de lo contrario lanzará un error de inicialización runtime.
⚠️
Buenas prácticas: En la arquitectura real de backend, se prefiere usar las declaraciones de funciones tradicionales para procesos estructurados o globales, y las expresiones de funciones cuando se desea encapsular lógica local o asignarla dinámicamente.

03Parámetros y Valor de Retorno

Para lograr que una función sea verdaderamente versátil y reutilizable, debe poder recibir datos del exterior y devolver resultados transformados procesados.

Parámetros vs. Argumentos

El Parámetro es el nombre de la variable de entrada definido entre los paréntesis durante la construcción de la función. El Argumento es el valor real y explícito que se le pasa al invocarla dinámicamente.

javascript
// 'a' y 'b' son parámetros (los ingredientes declarados)
function sumar(a, b) {
  return a + b; // La sentencia 'return' finaliza la ejecución y extrae el resultado
}

// 10 y 5 son los argumentos (los datos reales enviados)
const resultado = sumar(10, 5);
console.log(resultado); // Imprime: 15

// Reutilización con diferentes conjuntos de argumentos:
console.log(sumar(100, 200)); // Imprime: 300
console.log(sumar(3.5, 1.5));   // Imprime: 5

La importancia del control de retornos

La sentencia return interrumpe de forma inmediata el flujo de ejecución de la función actual. Si una función ejecuta todo su cuerpo de código interno sin encontrarse explícitamente con ningún return, devolverá por defecto el valor especial undefined.

Parámetros con valores por defecto

Podemos asignar valores de respaldo directo en la firma de la función para evitar valores undefined si el programador olvida pasar un argumento válido.

javascript
function saludarUsuario(nombre = 'usuario', saludo = 'Hola') {
  return `${saludo}, ${nombre}!`;
}

console.log(saludarUsuario('Ana', 'Bienvenida')); // 'Bienvenida, Ana!'
console.log(saludarUsuario('Carlos'));            // 'Hola, Carlos!'
console.log(saludarUsuario());                    // 'Hola, usuario!'

04Scope: El Alcance de las Variables

El Scope es la frontera lógica que determina desde qué partes exactas de tu archivo de código una variable en particular puede ser accedida o leída.

Ámbito (Scope) Reglas de Visibilidad y Acceso
Scope Global Variables declaradas en la raíz del archivo. Son visibles por cualquier función interna.
Scope Local / Función Variables declaradas con let o const dentro de las llaves de una función. Solo existen allí dentro; fuera de la función son completamente invisibles en memoria.
javascript
const mensajeGlobal = 'Soy global'; // Accesible en todo el archivo

function miFuncion() {
  const mensajeLocal = 'Soy local';
  console.log(mensajeGlobal); // OK: Puede acceder a lo global desde dentro
  console.log(mensajeLocal);  // OK: Existe en su propio scope interno
}

miFuncion();
console.log(mensajeGlobal); // OK: Imprime 'Soy global'
console.log(mensajeLocal);  // ERROR AUTOMÁTICO: mensajeLocal is not defined
🛡️
Ventaja de diseño: Esto garantiza un aislamiento total. Cada función administra de forma limpia su propio espacio conceptual de variables, evitando colisiones accidentales de datos con otras funciones externas.

05Funciones que Retornan Objetos y Retorno Temprano

En entornos de servidor, es un estándar absoluto que las funciones devuelvan estructuras compuestas de objetos para mapear éxitos, fallas y payloads de datos complejos.

El patrón de Retorno Temprano (Early Return) consiste en evaluar las condiciones de error o validaciones fallidas primero, saliendo de la función de inmediato y dejando el flujo principal libre de bloques anidados else.

javascript
function validarRegistro(nombre, email, password) {
  // Validación 1: Nombre obligatorio
  if (!nombre || nombre.trim() === '') {
    return { exito: false, error: 'El nombre es obligatorio' };
  }
  
  // Validación 2: Estructura básica de email
  if (!email || !email.includes('@')) {
    return { exito: false, error: 'Email inválido' };
  }
  
  // Validación 3: Seguridad de contraseña
  if (!password || password.length < 6) {
    return { exito: false, error: 'La password debe tener al menos 6 caracteres' };
  }
  
  // Si supera los filtros de error anteriores, se ejecuta el flujo exitoso directo
  return { exito: true, mensaje: 'Datos válidos' };
}

Uso práctico y técnicas combinadas con Destructuring

Podemos capturar las respuestas modulares de nuestras funciones de forma elegante en el backend utilizando desestructuración directa de propiedades:

javascript
const respuesta = validarRegistro('Ana', 'ana@mail.com', 'segura123');
console.log(respuesta); // { exito: true, mensaje: 'Datos válidos' }

// Desestructuración limpia para flujos de control lógicos:
const { exito, error, mensaje } = validarRegistro('', 'mail@error.com', '123');
if (exito) {
  console.log(mensaje);
} else {
  console.log('Error de procesamiento:', error); // Imprime: Error de procesamiento: El nombre es obligatorio
}

06Funciones como Valores (Callbacks)

En JavaScript, las funciones gozan del estatus de "First-Class Citizens" (Ciudadanos de primera clase). Esto significa que son tratadas como cualquier otro tipo de valor del lenguaje: pueden guardarse en variables, pasarse como argumentos a otras funciones o ser retornadas por otra función.

Una función que acepta a otra función como parámetro de entrada se conoce formalmente como Función de Orden Superior, mientras que la función enviada como argumento se denomina Callback.

javascript
// Función de Orden Superior que recibe un callback genérico
function ejecutarDosVeces(callback) {
  callback();
  callback();
}

function decirHola() {
  console.log('Hola!');
}

ejecutarDosVeces(decirHola); // Imprime 'Hola!' dos veces en la terminal

Procesamiento de arreglos mediante Callbacks dinámicos

Este patrón es la columna vertebral de métodos avanzados de iteración nativos de JavaScript y en el ecosistema asincrónico de Node.js.

javascript
function procesarUsuarios(usuarios, accion) {
  for (const u of usuarios) {
    accion(u); // Ejecuta el callback dinámico inyectado para cada elemento individual
  }
}

const lista = [{ nombre: 'Ana' }, { nombre: 'Luis' }];

// Pasando una expresión de función anónima como callback directo
procesarUsuarios(lista, function(u) {
  console.log(`Procesando en servidor: ${u.nombre}`);
});
