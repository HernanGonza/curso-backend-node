Asincronía en JavaScript

Entendé el mecanismo más importante de Node.js: por qué el código puede "esperar sin bloquear", cómo funciona el Event Loop, y cómo los callbacks asíncronos son la base de toda la arquitectura de servidores modernos.

60 minutos Requiere Clase 11
Objetivos de la clase
  • Comprender la diferencia fundamental entre código síncrono y asíncrono.
  • Entender qué es el Event Loop y por qué hace a Node.js tan eficiente.
  • Saber por qué Node.js es no-bloqueante y qué ventajas tiene para el backend.
  • Usar callbacks asíncronos con setTimeout y setInterval.
  • Reconocer el problema del Callback Hell y por qué hay que evitarlo.

01¿Qué es la Asincronía?

En programación, síncrono significa que cada línea de código espera a que la anterior termine para ejecutarse. El código avanza paso a paso, en orden, como una cola de supermercado donde cada cliente espera al anterior.

Asíncrono, en cambio, significa que ciertas operaciones pueden iniciarse y dejarse "en segundo plano" mientras el programa continúa ejecutando otras cosas. Cuando la operación termina, se avisa al programa mediante una función de retorno llamada callback.

🍕
Analogía real: Pedís una pizza por teléfono. Podés hacer otras cosas mientras la preparan. Cuando llega, el timbre (callback) te avisa. No te quedás parado mirando la puerta durante 40 minutos.

En el backend, las operaciones más lentas son: leer/escribir archivos en disco, consultar una base de datos, hacer requests a otras APIs, y esperar respuestas de red. Si el servidor se bloqueara esperando cada operación, solo podría atender una solicitud a la vez. La asincronía permite atender miles de solicitudes simultáneas.

02Síncrono vs. Asíncrono — La Diferencia Concreta

Código Síncrono — se ejecuta en orden estricto

javascript
console.log('Línea 1: inicio');
console.log('Línea 2: proceso');
console.log('Línea 3: fin');

// Output siempre en este orden:
// Línea 1: inicio
// Línea 2: proceso
// Línea 3: fin

Código Asíncrono — el orden de ejecución sorprende

javascript
console.log('1: antes del timeout');

setTimeout(function() {
  console.log('2: dentro del timeout (0ms)');
}, 0); // ← aunque sea 0ms, se ejecuta después

console.log('3: después del setTimeout');

// Output real:
// 1: antes del timeout
// 3: después del setTimeout     ← ¡primero!
// 2: dentro del timeout          ← después, aunque sean 0ms
⚠️
Concepto clave: El número de milisegundos en setTimeout no es un delay exacto. Es el tiempo mínimo que espera antes de encolar el callback. El Event Loop decide cuándo ejecutarlo.

03El Event Loop — El Corazón de Node.js

El Event Loop (bucle de eventos) es el mecanismo que permite a Node.js ejecutar código asíncrono sin bloquear el hilo principal. Funciona con una arquitectura de un solo hilo (single-threaded) pero maneja miles de operaciones concurrentes.

ComponenteQué hace
Call StackLa pila de ejecución. Aquí se ejecutan las funciones síncronas, una por vez, en orden LIFO (última en entrar, primera en salir).
Node APIsManejan operaciones asíncronas: timers (setTimeout), I/O (leer archivos, red). Trabajan en segundo plano fuera del stack.
Callback QueueCola donde esperan los callbacks listos para ejecutarse, una vez que el stack esté vacío.
Event LoopEl vigilante. Cuando el Call Stack está vacío, toma el primer callback de la Queue y lo mueve al Stack.
javascript
console.log('A');  // 1. Va al Stack → se ejecuta → sale

setTimeout(() => {
  console.log('B'); // 3. Event Loop lo mueve cuando el Stack está vacío
}, 1000);           // 2. Va a Node APIs → espera 1000ms → va a la Queue

console.log('C');  // 1. Va al Stack → se ejecuta → sale

// Output: A → C → B
💡
Por qué importa: El Event Loop es la razón por la que Node.js puede manejar miles de solicitudes simultáneas con un solo hilo. Mientras espera la respuesta de una base de datos, atiende otras solicitudes.

04¿Por qué Node.js es No-Bloqueante?

En lenguajes como PHP o Java tradicional, cuando el servidor consulta la base de datos, el hilo queda bloqueado: no puede hacer nada más hasta recibir la respuesta. Para atender múltiples usuarios simultáneos, se crean múltiples hilos, lo cual consume mucha memoria.

Node.js usa un modelo no-bloqueante: en lugar de esperar, registra un callback y continúa atendiendo otras solicitudes. Cuando la base de datos responde, el Event Loop ejecuta el callback.

Modelo BloqueanteModelo No-Bloqueante (Node.js)
1 usuario = 1 hilo bloqueado1 hilo atiende miles de usuarios
Alto consumo de memoriaBajo consumo de memoria
Escalabilidad costosaEscalabilidad muy eficiente
Ideal para CPU intensivoIdeal para I/O intensivo (APIs, bases de datos)
✅
Conclusión práctica: Node.js es ideal para APIs REST, servicios en tiempo real, y aplicaciones que hacen muchas operaciones de red o disco. No es la mejor opción para tareas que requieren mucho cómputo (procesamiento de video, cálculos matemáticos pesados).

05Callbacks Asíncronos: setTimeout y setInterval

Un callback asíncrono es una función que se ejecuta después de que ocurre un evento o pasa un tiempo determinado.

setTimeout — ejecutar una vez después de un delay

javascript
// Sintaxis: setTimeout(callback, milisegundos)
setTimeout(() => {
  console.log('Respuesta simulada del servidor');
}, 1500);

console.log('Esto se imprime primero, aunque venga después en el código');

setInterval — ejecutar repetidamente cada N milisegundos

javascript
let contador = 0;

const intervalo = setInterval(() => {
  contador++;
  console.log(`Tick #${contador}`);

  if (contador >= 3) {
    clearInterval(intervalo); // Detiene el intervalo
    console.log('Intervalo detenido');
  }
}, 1000);
// Output: Tick #1 ... Tick #2 ... Tick #3 ... Intervalo detenido

Simulando una operación de base de datos

javascript
function buscarUsuario(id, callback) {
  console.log(`Buscando usuario ${id} en la base de datos...`);

  // Simulamos 800ms de latencia de base de datos
  setTimeout(() => {
    const usuario = { id, nombre: 'Ana García', email: 'ana@mail.com' };
    callback(usuario); // Llamamos al callback con el resultado
  }, 800);
}

buscarUsuario(1, (usuario) => {
  console.log('Usuario encontrado:', usuario.nombre);
});

console.log('El servidor sigue atendiendo otras solicitudes...');
// Output:
// Buscando usuario 1 en la base de datos...
// El servidor sigue atendiendo otras solicitudes...
// Usuario encontrado: Ana García   ← después de 800ms

06Callback Hell — El Problema

Cuando se necesita encadenar varias operaciones asíncronas (buscar usuario → luego buscar sus pedidos → luego calcular el total), los callbacks se anidan cada vez más profundamente. Esto se llama Callback Hell o Pyramid of Doom.

javascript
// ⚠️ CALLBACK HELL — código difícil de leer y mantener
buscarUsuario(1, (usuario) => {
  console.log('Usuario:', usuario.nombre);

  buscarPedidos(usuario.id, (pedidos) => {
    console.log('Pedidos:', pedidos.length);

    calcularTotal(pedidos, (total) => {
      console.log('Total:', total);

      guardarResumen(usuario.id, total, (resultado) => {
        console.log('Guardado:', resultado);
        // Y si necesitás más operaciones... se sigue anidando
        // El código se vuelve imposible de mantener
      });
    });
  });
});
🔴
Por qué es un problema: El Callback Hell hace que el código sea muy difícil de leer, de depurar, y de manejar errores. Cada nivel de anidamiento es un nivel más de complejidad. Las Promesas (Clase 13) y async/await (Clase 14) resuelven este problema.
