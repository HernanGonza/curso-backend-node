Promesas en JavaScript

Superá el Callback Hell con la herramienta más importante de la asincronía: las Promesas. Aprendé a crear, encadenar y combinar promesas para escribir código asíncrono limpio, legible y con manejo de errores centralizado.

60 minutos Requiere Clase 12
Objetivos de la clase
  • Entender qué es una Promesa y qué problema resuelve respecto a los callbacks.
  • Conocer los tres estados de una Promesa: pending, fulfilled y rejected.
  • Consumir promesas usando .then() y manejar errores con .catch().
  • Encadenar múltiples operaciones asíncronas de forma limpia.
  • Usar Promise.all para ejecutar varias promesas en paralelo.
  • Crear promesas propias con new Promise(resolve, reject).

01¿Qué es una Promesa?

Una Promesa (Promise) es un objeto que representa el resultado eventual de una operación asíncrona. Es como un recibo: cuando pedís algo, te dan un papel que dice "te prometo entregarte el resultado cuando esté listo". Podés seguir haciendo cosas con ese papel antes de que llegue el resultado.

🎫
Analogía real: Es como pedir un trámite en el banco. Te dan un número de turno (la promesa). Podés seguir usando el celular mientras esperás. Cuando llaman tu número, la operación terminó: puede haber salido bien (fulfilled) o hubo un error (rejected).

Las Promesas resuelven el Callback Hell visto en la clase anterior. En lugar de anidar callbacks, las Promesas permiten encadenar operaciones asíncronas de forma lineal y legible.

02Los Tres Estados de una Promesa

EstadoSignificado y qué ocurre
pendingPendiente: Estado inicial. La operación asíncrona todavía está en curso. La promesa ni se resolvió ni fue rechazada.
fulfilledResuelta: La operación completó con éxito. Se ejecuta el callback del .then() con el valor resultante.
rejectedRechazada: La operación falló. Se ejecuta el callback del .catch() con el error.
⚠️
Regla importante: Una promesa solo puede pasar de pending a fulfilled, o de pending a rejected. Una vez resuelta o rechazada, su estado es definitivo y no puede cambiar.
javascript
const promesaExitosa = new Promise((resolve, reject) => {
  // Estado: PENDING → después de resolve(): FULFILLED
  resolve('Operación completada!');
});

const promesaFallida = new Promise((resolve, reject) => {
  // Estado: PENDING → después de reject(): REJECTED
  reject(new Error('Algo salió mal'));
});

03Consumir Promesas: .then() y .catch()

.then() registra una función que se ejecuta cuando la promesa se resuelve exitosamente. .catch() registra una función que se ejecuta cuando la promesa es rechazada.

javascript
function buscarUsuario(id) {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      if (id > 0) {
        resolve({ id, nombre: 'Ana García', email: 'ana@mail.com' });
      } else {
        reject(new Error('ID inválido'));
      }
    }, 500);
  });
}

// Caso exitoso:
buscarUsuario(1)
  .then(usuario => {
    console.log('Usuario encontrado:', usuario.nombre);
  })
  .catch(error => {
    console.log('Error:', error.message);
  });

// Caso fallido:
buscarUsuario(-1)
  .then(usuario => console.log(usuario))
  .catch(error => console.log('Error capturado:', error.message));
  // → 'Error capturado: ID inválido'

// .finally() — ejecuta siempre, con éxito o error:
buscarUsuario(1)
  .then(u  => console.log('OK:', u.nombre))
  .catch(e => console.log('Error:', e.message))
  .finally(() => console.log('Operación terminada'));

04Encadenamiento de Promesas

La gran ventaja de las Promesas es que se pueden encadenar. Cada .then() puede retornar una nueva promesa, y el siguiente .then() espera a que esa promesa se resuelva. El código queda lineal en lugar de anidado.

javascript
function buscarUsuario(id) {
  return new Promise(resolve =>
    setTimeout(() => resolve({ id, nombre: 'Ana' }), 300)
  );
}

function buscarPedidos(usuarioId) {
  return new Promise(resolve =>
    setTimeout(() => resolve([{ id: 101, total: 5000 }, { id: 102, total: 3200 }]), 300)
  );
}

// Encadenamiento limpio — sin anidamiento
buscarUsuario(1)
  .then(usuario => {
    console.log('Usuario:', usuario.nombre);
    return buscarPedidos(usuario.id); // ← retorna otra promesa
  })
  .then(pedidos => {
    console.log('Pedidos:', pedidos.length);
    const total = pedidos.reduce((sum, p) => sum + p.total, 0);
    return total;
  })
  .then(total => {
    console.log('Total de compras: $' + total);
  })
  .catch(error => {
    // Un solo .catch captura errores de TODA la cadena
    console.log('Error en algún paso:', error.message);
  });
✅
Ventaja clave: Un único .catch() al final de la cadena captura cualquier error que ocurra en cualquier .then() anterior. No necesitás manejar errores en cada paso.

05Promise.all — Ejecutar en Paralelo

Promise.all recibe un array de promesas y retorna una nueva promesa que se resuelve cuando todas las promesas se resuelven. Si cualquiera falla, Promise.all falla inmediatamente. Es ideal cuando necesitás varios datos independientes y no querés esperar uno por uno.

javascript
const promesaUsuario  = buscarUsuario(1);    // tarda 300ms
const promesaConfig   = buscarConfig();      // tarda 200ms
const promesaPermisos = buscarPermisos(1);   // tarda 400ms

// Sin Promise.all: 300 + 200 + 400 = 900ms totales
// Con Promise.all: max(300, 200, 400) = 400ms totales ✓

Promise.all([promesaUsuario, promesaConfig, promesaPermisos])
  .then(([usuario, config, permisos]) => {
    // Desestructuramos el array de resultados
    console.log('Usuario:', usuario.nombre);
    console.log('Config:', config.tema);
    console.log('Permisos:', permisos);
  })
  .catch(error => {
    console.log('Una de las operaciones falló:', error.message);
  });

Promise.race — La más rápida gana

Promise.race resuelve con el resultado de la primera promesa que complete. Es útil para implementar timeouts:

javascript
const consultaDB = buscarDatos();
const timeout = new Promise((_, reject) =>
  setTimeout(() => reject(new Error('Timeout: consulta tardó demasiado')), 3000)
);

Promise.race([consultaDB, timeout])
  .then(datos  => console.log('Datos recibidos:', datos))
  .catch(error => console.log('Error o timeout:', error.message));

06Crear Promesas con new Promise

Cuando querés "promesificar" una función que usa callbacks, podés envolverla en un new Promise. El constructor recibe una función ejecutora con dos parámetros: resolve (llamar cuando todo sale bien) y reject (llamar cuando falla).

javascript
// Función utilitaria: esperar N milisegundos
function esperar(ms) {
  return new Promise(resolve => setTimeout(resolve, ms));
}

// Función con resolve y reject:
function validarToken(token) {
  return new Promise((resolve, reject) => {
    if (!token) {
      reject(new Error('Token requerido'));
      return; // Importante: salir después de reject
    }
    if (token === 'token-valido-123') {
      resolve({ userId: 1, rol: 'admin' });
    } else {
      reject(new Error('Token inválido o expirado'));
    }
  });
}

validarToken('token-valido-123')
  .then(payload => console.log('Autenticado como:', payload.rol))
  .catch(error  => console.log('Auth fallida:', error.message));
