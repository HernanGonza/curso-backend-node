01¿Qué es Internet?

Internet es una red mundial de computadoras conectadas entre sí. Cuando abrís una app o una página web, tu dispositivo (el cliente) se comunica con otra computadora que está siempre encendida en algún lugar del mundo: el servidor.

02Frontend vs Backend

🎨
Frontend
  • • Lo que el usuario ve y toca
  • • Corre en tu dispositivo
  • • HTML, CSS, JavaScript
  • • Botones, formularios, colores
⚙️
Backend
  • • Lo que ocurre detrás de escena
  • • Corre en el servidor
  • • Node.js, Python, Java...
  • • Base de datos, lógica, seguridad
🍽️
Analogía del Restaurante: El Frontend es el salón (menú, mesas, mozos). El Backend es la cocina (ingredientes, recetas, preparación). El cliente pide → la cocina procesa → el mozo trae la respuesta.

03¿Qué es HTTP?

HTTP (HyperText Transfer Protocol) es el protocolo que usan clientes y servidores para comunicarse en internet. Cada vez que abrís una página, cargás una foto o iniciás sesión, se están enviando mensajes HTTP.

Métodos HTTP principales

MétodoAcciónEjemplo
GETLeer / obtener datosListar usuarios, ver un producto
POSTCrear datos nuevosRegistrarse, publicar un post
PUTReemplazar datos completosActualizar todo el perfil
PATCHModificar parcialmenteCambiar solo el nombre
DELETEEliminar datosBorrar una cuenta

04Flujo Request → Response

Cada interacción en la web sigue el mismo ciclo. El cliente envía una petición; el servidor la procesa y devuelve una respuesta.

1) Cliente hace clic o realiza una acción
→ Envía un HTTP Request al servidor
2) Servidor recibe el request
→ Procesa: lógica + consulta a la base de datos
3) Servidor arma el HTTP Response
→ Lo envía de vuelta al cliente
4) Cliente recibe y muestra el resultado

05Estructura del Request

Un Request tiene tres partes: la línea de inicio, los headers y (opcionalmente) el body.

HTTP Request — Login 
POST /api/login HTTP/1.1          ← línea de inicio: método + ruta + versión
Host: backend.curso.com           ← headers
Content-Type: application/json
Authorization: Bearer eyJhb...

{                                  ← body (solo en POST, PUT, PATCH)
  "email": "hernan@gmail.com",
  "password": "123456"
}
ParteEjemploQué es
Línea de inicioPOST /api/login HTTP/1.1Método + ruta + versión del protocolo
HeadersContent-Type: application/jsonMetadatos: tipo de datos, autenticación, etc.
Body{"email": "..."}Datos enviados. Solo en POST, PUT y PATCH.
💡
GET no tiene body. Los datos van en la URL: /api/productos?categoria=ropa&precio_max=5000 — esto se llama Query String.

06Estructura del Response

HTTP Response — Login exitoso 
HTTP/1.1 200 OK                    ← línea de estado
Content-Type: application/json     ← headers
Set-Cookie: session=abc123; HttpOnly

{                                   ← body con los datos
  "success": true,
  "mensaje": "Login exitoso",
  "token": "eyJhbGciOiJIUzI1NiJ9..."
}
HTTP Response — Password incorrecta 
HTTP/1.1 401 Unauthorized
Content-Type: application/json

{
  "success": false,
  "error": "Email o password incorrectos"
}

Códigos de estado más importantes

CódigoSignificadoCuándo ocurre
200 OKTodo salió bienRespuesta exitosa estándar
201 CreatedRecurso creadoPOST exitoso
204 No ContentOK sin datosDELETE exitoso
400 Bad RequestDatos mal enviadosFalta un campo, formato incorrecto
401 UnauthorizedNo autenticadoSin login o token inválido
403 ForbiddenSin permisoAutenticado pero sin acceso
404 Not FoundNo encontradoRuta o recurso inexistente

🔒
Seguridad: Cuando la password es incorrecta, el backend nunca dice "la password es incorrecta" ni "el email no existe". Siempre responde "Email o password incorrectos" sin especificar cuál. Si dijera cuál falló, un atacante podría probar emails hasta encontrar uno válido.

09Ejercicio Práctico — DevTools Network

🔍
Paso a paso con YouTube:
1) Abrí YouTube → F12 → pestaña Network → filtro Fetch/XHR → recargá con F5
2) Hacé clic en el primer request largo → pestaña Headers: mirá método, URL y status code
3) Pestaña Response: es el JSON crudo que devuelve el backend de YouTube
4) Columna Time: cuánto tardó en responder (buen backend < 200ms)

Lo que ves en Response es exactamente lo que el backend de YouTube le manda al frontend.
🔥
Desafío — encontrá estos 3 requests:
• Un GET a una URL con browse o next (el feed de videos)
• Un request con el header Authorization (te identifica como usuario logueado)
• Un request con Status 304 (el servidor dice: "ya tenés esa data en caché")
