Middlewares

Entendé el pipeline de Express en profundidad, escribí tus propios middlewares, y protegé rutas sensibles con un middleware simple de autenticación. Cierra el Bloque 5 de Express.

60 minutos Requiere Clase 23

  • Escribir middlewares propios con la firma (req, res, next) y entender el rol de next().
  • Comprender en profundidad express.json() como middleware incorporado de parseo del body.
  • Reconocer middlewares de terceros de uso frecuente, como morgan y cors.
  • Implementar un middleware simple de autenticación basado en un header y un token.

01¿Qué es un Middleware? El Pipeline de Express

Cuando un request llega a un servidor Express, no va directamente al handler de la ruta que lo va a responder. Antes, atraviesa una cadena de funciones que se ejecutan en orden, una tras otra. Cada una de esas funciones es un middleware: literalmente, "lo que está en el medio" entre la llegada del request y la respuesta final.

Un middleware es una función con la firma (req, res, next). Puede leer o modificar el request, escribir en la response, registrar información, verificar autenticación, o simplemente dejar pasar el request al siguiente eslabón de la cadena llamando a next(). Esta cadena completa se conoce como el pipeline de Express.

💡
Analogía práctica: Pensá en cada request como una persona entrando a un edificio de oficinas. Primero pasa por seguridad (autenticación), después firma el registro de ingreso (logging), y recién ahí llega a la oficina donde lo atienden (el handler de la ruta). Cada paso intermedio es un middleware.
javascript
function miMiddleware(req, res, next) {
  console.log('Paso por aca');
  next(); // Le cede el control al siguiente eslabon de la cadena
}

app.use(miMiddleware);
⚠️
Error grave y frecuente: Si un middleware no llama a next() ni envía una respuesta con res.json() o similar, el request queda colgado indefinidamente: el cliente nunca recibe respuesta y la conexión eventualmente expira.

02Registrando Middlewares con app.use()

app.use() es el método que registra un middleware en el pipeline de la aplicación. A diferencia de app.get() o app.post(), que solo actúan sobre un método HTTP específico, un middleware registrado con app.use() sin ruta se ejecuta para absolutamente todos los requests entrantes, sin importar el método o la URL.

javascript
const express = require('express');
const app = express();

// Middleware global: se ejecuta en TODOS los requests
app.use((req, res, next) => {
  console.log(`${req.method} ${req.url}`);
  next();
});

app.get('/productos', (req, res) => res.json([]));

El orden en que se registran los middlewares con app.use() es exactamente el orden en que se ejecutan. Un middleware registrado antes de las rutas se aplica a todas ellas; uno registrado después de una ruta específica nunca llega a ejecutarse para esa ruta.

03express.json(): El Middleware Incorporado más Usado

Ya usamos express.json() en clases anteriores para poder leer req.body, pero ahora podemos entender exactamente qué es: es un middleware incorporado (built-in) de Express. Su trabajo es interceptar el request, leer el cuerpo crudo enviado por el cliente, parsearlo como JSON, y dejarlo disponible en req.body antes de que la ruta lo reciba.

javascript
app.use(express.json()); // Debe ir ANTES de las rutas que necesiten req.body

app.post('/productos', (req, res) => {
  console.log(req.body); // Ya viene parseado como objeto JS
  res.status(201).json(req.body);
});
🛡️
Por qué el orden importa: Si express.json() se registra después de una ruta POST, esa ruta específica nunca va a tener acceso a req.body, porque el pipeline ya pasó por ese punto sin que el middleware llegara a parsear nada todavía.

04Middlewares de Terceros: morgan y cors

Además de los middlewares propios y los incorporados en Express, existe un ecosistema enorme de middlewares de terceros instalables por npm, que resuelven problemas comunes sin tener que reescribirlos desde cero.

PaqueteQué resuelve
morganRegistra automáticamente un log de cada request (método, URL, status, tiempo de respuesta) en la consola.
corsHabilita que un frontend alojado en otro dominio pueda consumir la API sin ser bloqueado por el navegador.
bash
npm install morgan cors
javascript
// index.js
const morgan = require('morgan');
const cors = require('cors');

app.use(morgan('dev'));
app.use(cors());

Esta es precisamente la razón por la que el patrón middleware es tan poderoso: cualquier funcionalidad transversal a toda la aplicación (logging, seguridad, compresión, etc.) se puede agregar con una sola línea, sin tocar el código de las rutas.

05Middleware de Autenticación Simple

Uno de los usos más importantes de los middlewares es la autenticación: verificar, antes de llegar al handler de la ruta, si el request tiene permiso para continuar. Un caso simple y muy didáctico es exigir un token fijo en un header personalizado.

javascript
function verificarToken(req, res, next) {
  const token = req.headers['x-auth-token'];

  if (!token || token !== 'secreto123') {
    return res.status(401).json({ error: 'No autorizado' });
  }

  next(); // El token es valido: dejamos pasar el request
}

// Se aplica unicamente a la ruta de borrado
app.delete('/productos/:id', verificarToken, (req, res) => {
  // ... logica de borrado, solo se ejecuta si paso el middleware
});
⚠️
Sobre el status 401: 401 (Unauthorized) es el código estándar para indicar que faltan credenciales válidas. En proyectos reales, el token no se hardcodea así: se genera dinámicamente con JWT, algo fuera del alcance de esta clase introductoria.

06Middlewares Globales vs. Middlewares por Ruta

Un middleware puede aplicarse de dos formas distintas: globalmente, con app.use() sin ruta (afecta a todos los requests), o de forma local, pasándolo como argumento intermedio de una ruta específica (afecta solo a esa ruta).

javascript
// Global: se ejecuta siempre, para cualquier ruta
app.use(express.json());

// Local: solo se ejecuta para esta ruta puntual
app.delete('/productos/:id', verificarToken, (req, res) => {
  // ...
});

// Tambien se pueden encadenar varios middlewares locales:
app.post('/productos', verificarToken, validarDatos, (req, res) => {
  // ...
});

El orden sigue siendo la regla de oro: Express ejecuta los middlewares y el handler final en el orden exacto en que aparecen escritos en la ruta, de izquierda a derecha.
