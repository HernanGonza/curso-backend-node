Condicionales

Aprendé a que tu programa tome decisiones: if, else, ternario y switch aplicados a validaciones y permisos reales de backend.

60 minutos Requiere Clase 4
Objetivos de la clase
  • Entender qué es una condición y para qué sirve en un programa.
  • Aprender a usar if, else if y else.
  • Conocer el operador ternario para condiciones simples.
  • Usar switch para manejar múltiples casos.
  • Aplicar condicionales a situaciones reales de backend: validaciones, permisos, respuestas HTTP.

01¿Qué es una Condición?

🤔
Condición = una pregunta que el programa se hace a sí mismo.
Una condición es una expresión que el programa evalúa como verdadera (true) o falsa (false). Según el resultado, el programa ejecuta un bloque de código u otro. Sin condicionales, un programa solo puede hacer una cosa — siempre la misma.
Ejemplo: si el email y la password son correctos, devuelve el token. Si no, devuelve un error 401. Eso es una condición.

Valores que JavaScript considera falsos (Falsy)

En JavaScript no solo false es falso. Hay otros valores que se comportan como false cuando se usan en una condición. Conocerlos evita bugs:

false
el booleano false
0
el número cero
''
string vacío
null
ausencia intencional de valor
undefined
variable no inicializada
NaN
Not a Number
✓
Truthy: todo lo demás es verdadero. Cualquier valor que no sea los 6 de arriba es considerado true en una condición. Por ejemplo: cualquier número distinto de 0, cualquier string no vacío, cualquier objeto o array. Esto es muy útil para verificar si una variable tiene valor: if (usuario) { ... }

02if / else if / else

if — si pasa esto, hacé esto

if es la estructura condicional más básica. Si la condición entre paréntesis es verdadera, ejecuta el bloque entre llaves. Si es falsa, lo saltea.

JavaScript
const edad = 20;

if (edad >= 18) {
  console.log('Es mayor de edad');
}
// Como edad es 20, la condicion es true y se imprime el mensaje.

// Si la condicion es falsa, nada se ejecuta:
const otraEdad = 15;
if (otraEdad >= 18) {
  console.log('Este mensaje NO se imprime');
}

else — si no, hacé esto otro

else se agrega después del if y contiene el código que se ejecuta cuando la condición del if es falsa. Siempre va a ejecutarse UNO de los dos bloques, nunca los dos.

JavaScript
const edad = 15;

if (edad >= 18) {
  console.log('Puede entrar');
} else {
  console.log('No puede entrar, es menor de edad');
}
// Como edad es 15, se ejecuta el else.

else if — si no, pero si esto otro...

else if agrega condiciones adicionales entre el if y el else. Se evalúan en orden: si la primera es false, se prueba la segunda, etc. Solo se ejecuta el primer bloque cuya condición sea true. Podés poner tantos else if como necesites.

JavaScript
const nota = 75;

if (nota >= 90) {
  console.log('Excelente');
} else if (nota >= 70) {
  console.log('Aprobado');   // <-- este se ejecuta
} else if (nota >= 50) {
  console.log('Regular');
} else {
  console.log('Desaprobado');
}

Ejemplo real de backend: validación de login

JavaScript
const email    = 'hernan@gmail.com';
const password = '123456';

// Simulacion de datos que vendrian de la base de datos
const emailEnDB    = 'hernan@gmail.com';
const passwordEnDB = '123456';

if (!email || !password) {
  // !email es true si email es vacio, null o undefined
  console.log('Error 400: email y password son obligatorios');
} else if (email !== emailEnDB) {
  console.log('Error 401: email o password incorrectos');
} else if (password !== passwordEnDB) {
  console.log('Error 401: email o password incorrectos');
} else {
  console.log('Login exitoso - generando token...');
}
🔒
¿Por qué el mismo mensaje para email y password incorrectos?
Nunca le digas al usuario cuál de los dos falló. Si decís "email no existe", un atacante puede probar emails hasta encontrar uno válido. Siempre el mensaje genérico: "email o password incorrectos".

03Operador Ternario

⚡
Operador ternario: condicion ? siTrue : siFalse
El operador ternario es una forma corta de escribir un if/else simple en una sola línea. Es muy usado en JavaScript moderno.
Estructura: condicion ? valorSiTrue : valorSiFalse
JavaScript
// Con if/else:
let mensaje;
if (edad >= 18) {
  mensaje = 'Mayor de edad';
} else {
  mensaje = 'Menor de edad';
}

// Con operador ternario (equivalente, mas corto):
const msg = edad >= 18 ? 'Mayor' : 'Menor';  // una sola linea

Ejemplos de uso real en backend

JavaScript
// Mensaje de bienvenida segun rol
const rol    = 'admin';
const saludo = rol === 'admin' ? 'Bienvenido administrador' : 'Bienvenido usuario';

// Descuento segun si es socio
const esSocio   = true;
const descuento = esSocio ? 0.20 : 0.05;           // 20% o 5%
const precioFinal = 1000 * (1 - descuento);
console.log(`Precio: $${precioFinal}`);             // $800

// Codigo HTTP de respuesta
const encontrado  = false;
const statusCode  = encontrado ? 200 : 404;
console.log(`Status: ${statusCode}`);               // 404
💡
Cuándo usar ternario y cuándo usar if/else:
Ternario: cuando la condición es simple y el resultado es un valor (no ejecutás código complejo).
if/else: cuando necesitás ejecutar varias líneas de código en cada rama, o cuando la condición tiene múltiples casos (else if). Si el ternario queda muy largo y difícil de leer, usá if/else.

04Switch: Múltiples Casos

🔀
Switch: cuando hay muchos if/else if seguidos.
Cuando necesitás comparar una variable contra muchos valores posibles, switch es más limpio que una cadena larga de else if. Evalúa la variable una vez y salta directamente al caso que coincide. Cada caso termina con break para evitar que siga ejecutando el siguiente.
JavaScript
const metodoHTTP = 'POST';

switch (metodoHTTP) {
  case 'GET':
    console.log('Leyendo datos');
    break;
  case 'POST':
    console.log('Creando datos');   // <-- este se ejecuta
    break;
  case 'PUT':
    console.log('Actualizando datos');
    break;
  case 'DELETE':
    console.log('Eliminando datos');
    break;
  default:
    console.log('Metodo no reconocido');
    break;
}
⚠️
No olvidés el break. Si no ponés break al final de un case, el código "cae" al siguiente case y lo ejecuta también. Esto se llama fallthrough y es un error muy común. Siempre poné break al final de cada case, excepto cuando quieras agrupar casos a propósito.

Agrupar casos — cuando varios casos hacen lo mismo

JavaScript
const dia = 'sabado';

switch (dia) {
  case 'lunes':
  case 'martes':
  case 'miercoles':
  case 'jueves':
  case 'viernes':
    console.log('Dia laborable');
    break;
  case 'sabado':
  case 'domingo':
    console.log('Fin de semana');   // <-- este se ejecuta
    break;
  default:
    console.log('Dia invalido');
}

05Condicionales en el Backend Real

En backend, los condicionales aparecen constantemente para validar datos, verificar permisos y devolver la respuesta correcta. Estos son los patrones más comunes que vas a usar en el curso:

Patrón 1 — Validación de campos obligatorios
// Siempre validar que los datos lleguen antes de usarlos
function procesarRegistro(nombre, email, password) {
  if (!nombre) {
    return 'Error: el nombre es obligatorio';
  }
  if (!email || !email.includes('@')) {
    return 'Error: el email no es valido';
  }
  if (!password || password.length < 6) {
    return 'Error: la password debe tener al menos 6 caracteres';
  }
  return 'Datos validos - procesando registro...';
}

console.log(procesarRegistro('Juan', 'juan@mail.com', '123456'));
console.log(procesarRegistro('', 'juan@mail.com', '123'));
Patrón 2 — Verificación de permisos
function verificarAcceso(usuario, recurso) {
  if (!usuario) {
    return { status: 401, mensaje: 'No autenticado' };
  }
  if (!usuario.activo) {
    return { status: 403, mensaje: 'Cuenta suspendida' };
  }
  if (recurso === 'admin' && !usuario.esAdmin) {
    return { status: 403, mensaje: 'No tenes permiso para esta seccion' };
  }
  return { status: 200, mensaje: 'Acceso permitido' };
}

const usuario1 = { nombre: 'Maria', activo: true, esAdmin: false };
console.log(verificarAcceso(usuario1, 'admin'));    // { status: 403, ... }
console.log(verificarAcceso(usuario1, 'perfil'));   // { status: 200, ... }
Patrón 3 — Respuesta según código HTTP
function manejarRespuesta(statusCode, datos) {
  if (statusCode === 200) {
    console.log('Exito:', datos);
  } else if (statusCode === 404) {
    console.log('No encontrado');
  } else if (statusCode === 401) {
    console.log('No autenticado - redirigir a login');
  } else if (statusCode >= 500) {
    console.log('Error del servidor - reintentar mas tarde');
  } else {
    console.log('Respuesta inesperada:', statusCode);
  }
}
