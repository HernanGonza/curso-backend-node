Crear Servidor con http

Creá tu primer servidor HTTP desde cero usando solo Node.js. Entendé la anatomía de un request y una response, el ciclo de vida completo de una solicitud, y cómo Node.js maneja miles de conexiones simultáneas sin bloquearse.

60 minutos Requiere Clase 15
Objetivos de la clase
  • Entender qué es un servidor HTTP y cómo funciona el ciclo request-response.
  • Crear un servidor HTTP con el módulo nativo de Node.js.
  • Comprender los objetos req y res y su diferencia conceptual.
  • Usar res.write() y res.end() correctamente.
  • Entender el ciclo de vida completo de un request en 8 pasos.
  • Usar variables de entorno para configurar el puerto del servidor.

01¿Qué es un Servidor HTTP?

Para entender qué hace Node.js cuando creamos un servidor, primero hay que entender qué es un servidor HTTP a nivel conceptual. Un servidor HTTP es un programa que permanece en ejecución y escucha en un número de puerto de red. Un puerto es un número del 0 al 65535 que identifica un servicio específico dentro de una misma dirección IP: el 80 es el estándar para HTTP, el 443 para HTTPS, el 5432 para PostgreSQL, y en desarrollo usamos el 3000 por convención.

Cuando un cliente (un navegador, Postman, o cualquier aplicación) quiere comunicarse con el servidor, establece una conexión hacia la IP del servidor y el puerto donde está escuchando. El servidor detecta esa conexión, lee el mensaje HTTP que envió el cliente —el request— y devuelve una respuesta HTTP —el response. Ese intercambio completo es el ciclo request-response.

💡
El servidor es reactivo: Un servidor HTTP no hace nada por su cuenta. Simplemente espera. Toda acción es una reacción a un request entrante. Esta arquitectura se llama modelo cliente-servidor y es la base de toda la web.

02http.createServer — Crear el Servidor

El módulo nativo http de Node.js provee todo lo necesario para crear un servidor HTTP sin instalar ningún paquete externo. La función central es http.createServer().

createServer() recibe como argumento una función —llamada función manejadora o request handler— que se ejecutará cada vez que llegue un nuevo request. Esta función recibe dos objetos: req (el request entrante, con toda la información del cliente) y res (el objeto para construir y enviar la respuesta).

createServer() no inicia la escucha por sí solo: solo crea el servidor. Para que empiece a aceptar conexiones, hay que llamar al método .listen() con el número de puerto. El callback de listen se ejecuta una sola vez cuando el servidor está listo.

javascript
const http = require('http');

// createServer recibe el callback que se ejecuta en CADA request:
const servidor = http.createServer((req, res) => {
  // req = informacion del request entrante (solo lectura)
  // res = herramientas para construir y enviar la respuesta
  res.end('Hola desde Node.js!');
});

// Sin .listen(), el servidor existe pero no escucha nada.
// El callback de listen se ejecuta UNA SOLA VEZ cuando esta listo.
servidor.listen(3000, () => {
  console.log('Servidor corriendo en http://localhost:3000');
});
✅
Para probarlo: Ejecutá node server.js en la terminal y abrí http://localhost:3000 en el navegador.

03Los Objetos req y res

La función manejadora que pasamos a createServer recibe siempre dos objetos. Entenderlos es fundamental porque son la interfaz entre tu código y el cliente que hace el request.

El objeto req (request) es de solo lectura. Contiene toda la información de la solicitud entrante: la URL que pidió el cliente (req.url), el método HTTP utilizado (req.method), los headers enviados (req.headers), y el cuerpo del mensaje para requests POST o PUT. Pensálo como el sobre y la carta que envió el cliente: podés leer todo su contenido pero no modificarlo.

El objeto res (response) es de solo escritura. Es el conjunto de herramientas para construir la respuesta: podés setear el status code, agregar headers, escribir el cuerpo, y finalmente cerrarlo. Pensálo como la hoja en blanco donde vas a escribir tu respuesta.

ObjetoLectura/EscrituraContiene / Permite
reqSolo lecturareq.url, req.method, req.headers, el body del request
resSolo escriturares.writeHead(), res.write(), res.end(), res.setHeader()

04res.write() y res.end() — Construir la Respuesta

Una respuesta HTTP tiene dos partes: los headers (metadatos: status code, tipo de contenido, cookies) y el body (el cuerpo: el HTML, el JSON, el archivo). En Node.js nativo, estas partes se construyen con métodos distintos.

res.writeHead(statusCode, headers) envía el status code y los headers. Solo puede llamarse una vez y debe hacerse antes de escribir el cuerpo. res.write(fragmento) escribe un fragmento del cuerpo; puede llamarse varias veces. res.end() es obligatorio: cierra la respuesta. Si no lo llamás, la conexión queda abierta y el cliente esperará indefinidamente hasta que expire el timeout.

javascript
const servidor = http.createServer((req, res) => {

  // PASO 1: status code + headers (antes del cuerpo)
  res.writeHead(200, { 'Content-Type': 'text/html; charset=utf-8' });

  // PASO 2: cuerpo de la respuesta (puede llamarse varias veces)
  res.write('
Bienvenido a mi servidor
');
  res.write('
Node.js funcionando correctamente
');

  // PASO 3: cerrar la respuesta - SIEMPRE obligatorio
  res.end();
  // O todo en uno: res.end('
ultimo contenido
');
});

05Ciclo de Vida de un Request — Paso a Paso

Entender exactamente qué pasa cuando llega un request al servidor es esencial para poder depurar problemas y diseñar la lógica correctamente. El flujo completo:

1. Cliente envíaEl navegador o Postman construye un mensaje HTTP y lo envía a la IP:puerto del servidor
2. Conexión TCPSe establece la conexión. Node.js detecta la nueva conexión en el puerto 3000
3. Node.js parseaEl módulo http parsea automáticamente la cabecera HTTP y crea los objetos req y res
4. Callback ejecutaNode.js llama a tu función manejadora (req, res) => { ... }
5. Tu código procesaLeés req.url y req.method para saber qué quiere el cliente y aplicás la lógica

7. res.end()La respuesta completa se envía al cliente y la conexión TCP se cierra

06Variables de Entorno y el Puerto

Codificar directamente el número de puerto en el código (lo que se llama hardcodear) es una mala práctica. Las plataformas de deployment en producción como Render o Railway asignan el puerto dinámicamente mediante una variable de entorno llamada PORT. Si tu código dice listen(3000), el servidor no arrancará en producción porque intenta escuchar en el puerto 3000, que no es el que la plataforma asignó.

Las variables de entorno son valores de configuración que el sistema operativo o la plataforma pone a disposición del programa. En Node.js se acceden con process.env. El patrón process.env.PORT || 3000 significa: usá el puerto de la variable de entorno PORT; si no existe (desarrollo local), usá el 3000 como fallback.

javascript
const PUERTO = process.env.PORT || 3000;

const servidor = http.createServer((req, res) => {
  res.setHeader('Content-Type', 'text/plain; charset=utf-8');

  if (req.url === '/') {
    res.writeHead(200);
    res.end('Bienvenido a la API!');

  } else if (req.url === '/salud') {
    res.writeHead(200);
    res.end('OK - Uptime: ' + process.uptime().toFixed(0) + 's');

  } else {
    res.writeHead(404);
    res.end('404 - Ruta no encontrada');
  }
});

servidor.listen(PUERTO, () => {
  console.log(`Servidor en http://localhost:${PUERTO}`);
});
