Params y Query

Dominá a fondo req.params, req.query y req.body, aprendé a combinarlos en un mismo endpoint, e implementá paginación y filtrado sobre una colección de productos.

60 minutos Requiere Clase 22
Objetivos de la clase
  • Comprender en profundidad qué es req.params y cómo capturar segmentos dinámicos dentro de una URL.
  • Comprender en profundidad qué es req.query y cómo se usa para filtros y parámetros opcionales.
  • Repasar y afianzar el uso de req.body para recibir datos estructurados en el cuerpo de la petición.
  • Combinar params, query y body dentro de un mismo endpoint según la necesidad de cada caso.
  • Implementar paginación manual sobre una colección en memoria usando page y limit.

01req.params: Segmentos Dinámicos de la URL

req.params captura los valores que forman parte de la estructura misma de la URL. Cuando definimos una ruta como /productos/:id, el segmento :id es un marcador de posición: cualquier valor que aparezca ahí queda disponible en req.params.id.

La característica central de req.params es que identifica de forma obligatoria y única a un recurso específico. No tiene sentido pedir /productos/:id sin un id: la ruta directamente no existiría sin ese valor.

javascript
app.get('/productos/:id', (req, res) => {
  console.log(req.params); // { id: '3' }
  const producto = productos.find(p => p.id === Number(req.params.id));
  res.json(producto);
});

// Se pueden combinar varios parametros dinamicos en la misma ruta:
app.get('/categorias/:catId/productos/:prodId', (req, res) => {
  console.log(req.params); // { catId: '2', prodId: '7' }
});
⚠️
Detalle importante: req.params siempre entrega los valores como strings, aunque en la URL parezcan números. Por eso, al comparar contra un id numérico, se usa Number(req.params.id) para convertir el tipo antes de comparar.

02req.query: Parámetros Opcionales de Filtro

req.query captura los valores que aparecen después del signo ? en la URL, conocidos como query string. A diferencia de params, estos valores son siempre opcionales: la ruta funciona perfectamente sin ellos, y su propósito habitual es filtrar, ordenar o modificar el resultado de una consulta.

javascript
// GET /productos?categoria=electronica&orden=precio
app.get('/productos', (req, res) => {
  console.log(req.query); // { categoria: 'electronica', orden: 'precio' }
  let resultado = productos;
  if (req.query.categoria) {
    resultado = resultado.filter(p => p.categoria === req.query.categoria);
  }
  res.json(resultado);
});

03req.body: Repaso y Casos Avanzados

req.body ya lo usamos en la Clase 22 para recibir los datos de un POST o PUT. Vale la pena recordar por qué existe: a diferencia de params y query, que viajan en la URL con un límite práctico de longitud, el body permite enviar estructuras de datos completas y anidadas en el cuerpo de la petición, sin restricción de tamaño relevante para un formulario típico.

🛡️
Requisito indispensable: req.body solo existe si el middleware express.json() está registrado con app.use(express.json()) antes de las rutas. Sin ese middleware, req.body llega undefined incluso si el cliente envió un JSON válido.

Una validación básica y habitual antes de usar los datos del body es verificar que los campos obligatorios efectivamente llegaron:

javascript
app.post('/productos', (req, res) => {
  const { nombre, precio } = req.body;
  if (!nombre || precio === undefined) {
    return res.status(400).json({ error: 'Nombre y precio son obligatorios' });
  }
  // ... continua la creacion
});

05Paginación: Controlando el Volumen de Resultados

Cuando una colección tiene miles de registros, devolver todos de una sola vez en un GET es poco práctico tanto para el servidor como para quien consume la API. La paginación resuelve esto: en vez de devolver todo, se devuelve un "recorte" (página) de un tamaño acotado.

La convención más común usa dos query params: page (qué página se pide) y limit (cuántos elementos por página).

javascript
// GET /productos?page=2&limit=10
app.get('/productos', (req, res) => {
  const page = Number(req.query.page) || 1;
  const limit = Number(req.query.limit) || 10;
  const inicio = (page - 1) * limit;
  const fin = inicio + limit;

  res.json({
    pagina: page,
    total: productos.length,
    resultados: productos.slice(inicio, fin)
  });
});
💡
Analogía práctica: Es exactamente igual a los resultados de un buscador web: nunca te muestra los diez millones de resultados juntos, sino \u00ab10 resultados de la página 1\u00bb con un botón para pasar a la siguiente. slice(inicio, fin) es lo que arma ese recorte dentro del array completo.

06Filtrado y Búsqueda Combinando Query Params

Los query params se pueden combinar libremente para armar filtros más ricos. Es una práctica común encadenar varias condiciones antes de aplicar la paginación, para que el usuario pueda buscar, filtrar y paginar al mismo tiempo.

javascript
// GET /productos?categoria=electronica&precioMax=5000&page=1&limit=5
app.get('/productos', (req, res) => {
  let resultado = productos;

  if (req.query.categoria) {
    resultado = resultado.filter(p => p.categoria === req.query.categoria);
  }
  if (req.query.precioMax) {
    resultado = resultado.filter(p => p.precio <= Number(req.query.precioMax));
  }

  // luego se le aplica la paginacion de la seccion anterior sobre "resultado"
  res.json(resultado);
});
