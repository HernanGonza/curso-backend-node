Async / Await

Dominá la sintaxis más elegante para código asíncrono. Async/await te permite escribir Promesas que se leen como código síncrono, con manejo de errores natural con try/catch y sin cadenas de .then().

60 minutos Requiere Clase 13
Objetivos de la clase
  • Entender qué es async/await y qué relación tiene con las Promesas.
  • Declarar funciones asíncronas con la palabra clave async.
  • Pausar la ejecución de forma elegante con await.
  • Manejar errores en código asíncrono con try/catch.
  • Usar await dentro de bucles para operaciones secuenciales.
  • Combinar async/await con Promise.all para operaciones paralelas.

01¿Qué es async/await?

async/await es azúcar sintáctica sobre las Promesas: no es un mecanismo nuevo, sino una forma más limpia y legible de escribir el mismo código asíncrono. Fue introducida en ES2017.

La idea es que el código asíncrono se vea y se lea como código síncrono, sin cadenas de .then(). Esto facilita enormemente la comprensión y el mantenimiento.

💡
Concepto clave: async/await no reemplaza las Promesas: las usa por debajo. Una función async siempre retorna una Promesa. await solo pausa la ejecución dentro de esa función, nunca bloquea el Event Loop.

02La palabra clave async

Agregar async antes de una función hace dos cosas: la convierte en asíncrona, y hace que siempre retorne una Promesa. Si retornás un valor normal, se envuelve automáticamente en una Promesa resuelta.

javascript
// Función async — siempre retorna una Promesa
async function obtenerMensaje() {
  return 'Hola desde async';
}

// Es exactamente equivalente a:
function obtenerMensaje() {
  return Promise.resolve('Hola desde async');
}

// Ambas se consumen igual:
obtenerMensaje().then(msg => console.log(msg)); // 'Hola desde async'

// Arrow function async:
const obtenerDatos = async () => {
  return { ok: true, datos: [] };
};

03La palabra clave await

await solo se puede usar dentro de una función async. Pausa la ejecución de la función hasta que la Promesa se resuelva, y retorna el valor resuelto directamente — sin necesidad de .then().

javascript
function buscarUsuario(id) {
  return new Promise(resolve =>
    setTimeout(() => resolve({ id, nombre: 'Ana García' }), 500)
  );
}

function buscarPedidos(userId) {
  return new Promise(resolve =>
    setTimeout(() => resolve([{ id: 1, total: 5000 }]), 300)
  );
}

// ✓ Con async/await — lineal, limpio, fácil de leer
async function cargarPerfil(userId) {
  const usuario = await buscarUsuario(userId);  // espera 500ms
  console.log('Usuario:', usuario.nombre);

  const pedidos = await buscarPedidos(usuario.id); // espera 300ms
  console.log('Pedidos:', pedidos.length);

  const total = pedidos.reduce((sum, p) => sum + p.total, 0);
  console.log('Total: $' + total);

  return { usuario, pedidos, total };
}

cargarPerfil(1);

04Manejo de Errores con try/catch

En lugar de .catch(), con async/await se usa el bloque try/catch tradicional de JavaScript. Si la promesa awaiteada es rechazada, el error se lanza como una excepción y catch lo captura.

javascript
async function procesarPago(monto, tarjeta) {
  try {
    // Validaciones síncronas primero (Early Return)
    if (monto <= 0) throw new Error('El monto debe ser mayor a cero');
    if (!tarjeta)   throw new Error('Tarjeta requerida');

    // Operaciones asíncronas
    const validacion = await validarTarjeta(tarjeta);
    const cobro      = await realizarCobro(monto, validacion.token);
    const recibo     = await generarRecibo(cobro.id);

    console.log('Pago exitoso. Recibo #' + recibo.numero);
    return { exito: true, recibo };

  } catch (error) {
    // Captura cualquier error de validación O de las promesas
    console.log('Error en pago:', error.message);
    return { exito: false, error: error.message };
  }
}

procesarPago(1500, '4539-xxxx-xxxx-1234').then(resultado => {
  console.log(resultado.exito ? '✓ OK' : '✗ Falló');
});
⚠️
Patrón recomendado: Siempre envolvé el cuerpo de una función async en try/catch. Un error no capturado en una función async genera una Promesa rechazada sin manejar, lo cual puede crashear tu servidor en Node.js.

05await en Bucles

Hay dos estrategias para procesar arrays de forma asíncrona según si las operaciones deben ser secuenciales o paralelas:

Secuencial — for...of con await (una espera a la anterior)

javascript
async function procesarEnSerie(pedidos) {
  const resultados = [];
  for (const pedido of pedidos) {
    // await dentro del for...of funciona correctamente
    const resultado = await procesarPedido(pedido.id);
    resultados.push(resultado);
    console.log(`Pedido ${pedido.id} procesado`);
  }
  return resultados;
  // Total: suma de todos los tiempos individuales
}

Paralelo — Promise.all (todas a la vez)

javascript
async function procesarEnParalelo(pedidos) {
  // map crea un array de Promesas sin esperarlas
  const promesas = pedidos.map(pedido => procesarPedido(pedido.id));

  // await Promise.all espera a que TODAS terminen
  const resultados = await Promise.all(promesas);
  return resultados;
  // Total: tiempo del pedido más lento (mucho más eficiente)
}

// ⚠️ NUNCA HACER ESTO — forEach NO respeta el await
// pedidos.forEach(async (pedido) => {
//   await procesarPedido(pedido.id); // NO funciona como se espera
// });
✅
Regla práctica: Usá for...of con await para operaciones que dependen una de la anterior. Usá Promise.all para operaciones independientes que pueden ejecutarse en paralelo.

javascript
// La misma operación — comparación directa:

// Versión con .then():
buscarUsuario(1)
  .then(u => buscarPedidos(u.id))
  .then(p => console.log('Pedidos:', p.length))
  .catch(e => console.log('Error:', e.message));

// Versión con async/await (mismo resultado, más legible):
async function mostrarPedidos() {
  try {
    const u = await buscarUsuario(1);
    const p = await buscarPedidos(u.id);
    console.log('Pedidos:', p.length);
  } catch (e) {
    console.log('Error:', e.message);
  }
}

07Patrón Real de Backend con async/await

Así se ve un endpoint de Express usando async/await — exactamente como lo vas a escribir en el Bloque 5 del curso:

javascript
// Endpoint GET /usuarios/:id — patrón real de producción
app.get('/usuarios/:id', async (req, res) => {
  try {
    const { id } = req.params;

    // Validación síncrona primero
    if (!id || isNaN(id)) {
      return res.status(400).json({ error: 'ID inválido' });
    }

    // Consulta a la base de datos (asíncrona)
    const usuario = await db.query(
      'SELECT * FROM usuarios WHERE id = $1',
      [id]
    );

    if (!usuario) {
      return res.status(404).json({ error: 'Usuario no encontrado' });
    }

    res.json(usuario);

  } catch (error) {
    // Cualquier error inesperado → 500 Internal Server Error
    console.error('Error interno:', error.message);
    res.status(500).json({ error: 'Error interno del servidor' });
  }
});
