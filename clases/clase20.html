Introducción a Express

Después de construir un servidor desde cero en el Bloque 4, llega Express. Descubrí qué agrega este framework sobre el módulo http nativo, cómo definir rutas de forma declarativa, cómo acceder a parámetros, query strings y el body del request, y cómo enviar respuestas JSON con el status correcto.

60 minutos Requiere Clase 19
Objetivos de la clase
  • Entender qué es Express y qué agrega sobre el módulo http nativo.
  • Instalar Express e inicializar un servidor con app.listen().
  • Definir rutas con app.get(), app.post(), app.put() y app.delete().
  • Usar res.json(), res.status() y res.sendStatus().
  • Acceder a parámetros de ruta con req.params y a query strings con req.query.
  • Configurar express.json() para parsear el body automáticamente.

01¿Qué es Express y por qué usarlo?

En las clases 15 a 19 construimos un servidor HTTP desde cero usando el módulo nativo http de Node.js. Lo hicimos deliberadamente: entender cómo funciona el servidor por debajo es fundamental para no usar las herramientas como cajas negras. Viste lo que implica: parsear la URL manualmente, extraer parámetros con expresiones regulares, leer el body como stream de eventos, construir una función helper para enviar JSON, y manejar el routing con bloques if/else.

Express es un framework minimalista para Node.js que resuelve exactamente todos esos problemas. No es un lenguaje nuevo: es una capa de abstracción construida sobre el módulo http nativo. Internamente, Express sigue haciendo exactamente lo mismo que hiciste vos. La diferencia es que lo hace con una API limpia y te libera de escribir ese código repetitivo en cada proyecto.

Express es el framework de Node.js más utilizado en el mundo. La enorme mayoría de los tutoriales, proyectos open source y APIs de producción en el ecosistema Node.js usan Express o están inspirados en su arquitectura.

💡
¿Qué agrega Express sobre Node.js nativo? Routing declarativo con parámetros automáticos (app.get('/usuarios/:id')), sistema de middlewares, helpers de respuesta (res.json(), res.status()), manejo estructurado de errores, y compatibilidad con miles de paquetes del ecosistema.

02Instalación y Primer Servidor con Express

Express se instala como cualquier paquete de npm. Una vez instalado, el archivo de entrada importa Express, crea una instancia de la aplicación llamando a la función express(), define las rutas, y llama al método listen() para iniciar el servidor.

La variable que se llama por convención app es el objeto central de toda la aplicación Express. A través de este objeto se definen todas las rutas, se registran middlewares, y se configura el servidor. Equivale al objeto que crearías con http.createServer(), pero con decenas de métodos adicionales.

javascript
// En la terminal:
// npm install express

const express = require('express');

// express() crea la instancia de la aplicacion.
// Todo el servidor vive en este objeto 'app'.
const app = express();

// Definir una ruta GET:
app.get('/', (req, res) => {
  res.json({ mensaje: 'API Express funcionando' });
});

// Iniciar el servidor:
app.listen(3000, () => {
  console.log('Servidor Express en http://localhost:3000');
});
✅
Compár con Node.js nativo: Con http nativo: crear servidor, parsear URL, verificar método, manejar 404 manualmente. Con Express: app.get('/ruta', handler) hace todo en una sola línea declarativa.

03Métodos HTTP en Express

Express provee un método de app por cada método HTTP. El nombre coincide con el método HTTP en minúsculas: app.get() para GET, app.post() para POST, app.put() para PUT, app.delete() para DELETE. Cada uno recibe la ruta y la función manejadora que se ejecuta cuando llega un request que coincide.

La función manejadora siempre recibe tres argumentos: req (el request), res (la response) y opcionalmente next (para pasar el control al siguiente middleware). Esto es idéntico al módulo http nativo pero con una API mucho más limpia.

javascript
app.get('/api/usuarios', (req, res) => {
  res.json({ data: usuarios });
});

app.post('/api/usuarios', (req, res) => {
  res.status(201).json({ mensaje: 'Creado' });
});

app.put('/api/usuarios/:id', (req, res) => {
  res.json({ mensaje: 'Actualizado' });
});

app.delete('/api/usuarios/:id', (req, res) => {
  res.sendStatus(204); // sin body
});

04Métodos de Respuesta — res.json(), res.status()

En Node.js nativo, enviar una respuesta JSON requeria llamar a res.writeHead() con el status y los headers, serializar el objeto con JSON.stringify(), y finalmente res.end(). Express simplifica todo esto en métodos de alto nivel que hacen la misma operación en una sola llamada.

res.json(objeto) serializa el objeto, setea automáticamente el header Content-Type: application/json, y envía la respuesta con status 200 por defecto. res.status(codigo) permite cambiar el status code antes de enviar. Como devuelve el mismo objeto res, se puede encadenar: res.status(201).json(objeto).

javascript
// Respuesta JSON con status 200 (por defecto):
res.json({ ok: true, data: usuarios });

// Status personalizado encadenado:
res.status(201).json({ ok: true, data: nuevoUsuario });
res.status(400).json({ ok: false, error: 'Datos invalidos' });
res.status(404).json({ ok: false, error: 'No encontrado' });

// Solo status, sin cuerpo (para DELETE exitoso):
res.sendStatus(204);

// Texto plano:
res.send('Servidor funcionando');

05req.params — Parámetros de Ruta

Cuando Express define una ruta con el patrón '/usuarios/:id', los dos puntos (:) indican que ese segmento de la URL es un parámetro de ruta dinámico. Express extrae automáticamente el valor de ese segmento y lo pone en el objeto req.params. Si el request es a /usuarios/42, entonces req.params.id será el string '42'.

Detalle importante: req.params.id siempre es un string, aunque la URL contenga un número. Si necesitás usarlo como número (por ejemplo, para buscar en la base de datos), hay que convertirlo con parseInt(req.params.id). Si la conversión falla, parseInt devuelve NaN, lo que debería disparar un error 400.

javascript
// La ruta define :id como parametro dinamico:
app.get('/api/usuarios/:id', (req, res) => {
  const id = parseInt(req.params.id);

  if (isNaN(id)) {
    return res.status(400).json({ error: 'ID debe ser un numero' });
  }

  const usuario = usuarios.find(u => u.id === id);
  if (!usuario) {
    return res.status(404).json({ error: 'Usuario no encontrado' });
  }

  res.json({ data: usuario });
});

// Multiples parametros:
app.get('/api/usuarios/:userId/posts/:postId', (req, res) => {
  const { userId, postId } = req.params; // desestructuracion
  res.json({ userId, postId });
});

06req.query — Query Strings

Los query strings son los parámetros que van en la URL después del signo ?, separados por &. Por ejemplo: /api/usuarios?pagina=2&limite=10&buscar=ana. Se usan para filtrado, paginación, búsqueda y cualquier dato opcional que el cliente quiera enviar junto a un request GET.

Express parsea estos parámetros automáticamente: todos quedan disponibles en el objeto req.query, donde cada clave es un parámetro. Siguen siendo strings, así que los números deben convertirse con parseInt() o parseFloat().

javascript
// Request: GET /api/usuarios?pagina=2&limite=10&buscar=ana
app.get('/api/usuarios', (req, res) => {
  console.log(req.query); // { pagina: '2', limite: '10', buscar: 'ana' }

  const pagina = parseInt(req.query.pagina) || 1;
  const limite = parseInt(req.query.limite) || 20;
  const buscar = req.query.buscar || '';

  let resultado = usuarios;
  if (buscar) {
    resultado = usuarios.filter(u =>
      u.nombre.toLowerCase().includes(buscar.toLowerCase())
    );
  }

  const inicio    = (pagina - 1) * limite;
  const paginados = resultado.slice(inicio, inicio + limite);

  res.json({ data: paginados, total: resultado.length, pagina, limite });
});

07req.body — Leer el Body con express.json()

Cuando un cliente hace un POST o PUT, envía datos en el cuerpo (body) del request en formato JSON. En Node.js nativo, leer ese body implicaba escuchar eventos de stream. Con Express, existe un middleware incorporado llamado express.json() que lo hace automáticamente.

Un middleware es una función que se ejecuta antes de llegar al handler de la ruta. express.json() detecta si el request tiene Content-Type: application/json, lee el body, lo parsea con JSON.parse(), y pone el resultado en req.body. Si no registrás este middleware, req.body será undefined en todos los endpoints.

javascript
const app = express();

// IMPORTANTE: registrar express.json() ANTES de las rutas
// Sin esto, req.body sera undefined en todos los endpoints
app.use(express.json());

app.post('/api/usuarios', (req, res) => {
  // req.body ya viene parseado automaticamente:
  const { nombre, email, password } = req.body;

  if (!nombre || !email || !password) {
    return res.status(400).json({
      ok: false,
      error: 'nombre, email y password son obligatorios'
    });
  }

  const nuevo = { id: nextId++, nombre, email };
  usuarios.push(nuevo);
  res.status(201).json({ ok: true, data: nuevo });
});
⚠️
En Postman: Para probar endpoints POST con body JSON, seleccioná Body → raw → JSON y escribí el objeto. Sin Content-Type: application/json, Express no parseará el body.
