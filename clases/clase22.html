CRUD con Rutas

Implementá las cuatro operaciones CRUD sobre un recurso en memoria, y aprendé a organizar el código con express.Router() y controllers separados en lugar de amontonar todo en un archivo único.

60 minutos Requiere Clase 21
Objetivos de la clase
  • Comprender el mapeo entre las operaciones CRUD (Crear, Leer, Actualizar, Borrar) y los métodos HTTP en una API REST.
  • Implementar los cuatro métodos (GET, POST, PUT, DELETE) sobre un recurso en memoria.
  • Identificar por qué mezclar rutas y lógica de negocio en un único archivo se vuelve insostenible.
  • Separar las rutas en express.Router() dentro de la carpeta routes/.
  • Extraer la lógica de negocio a funciones controller dentro de la carpeta controllers/.
  • Conectar routes/ y controllers/ mediante importaciones, dejando index.js limpio y desacoplado.

01CRUD: Las Cuatro Operaciones Fundamentales

Prácticamente cualquier sistema que maneje datos —una tienda, una red social, un banco— necesita resolver las mismas cuatro operaciones básicas sobre esos datos: crearlos, leerlos, modificarlos y borrarlos. Esa sigla, CRUD, viene del inglés Create, Read, Update, Delete, y es uno de los conceptos más transversales de todo el desarrollo backend.

Cuando trabajamos con una API REST, cada una de esas cuatro operaciones se mapea de forma convencional a un método HTTP específico. Esta convención no es obligatoria a nivel técnico —Express te deja usar cualquier método para cualquier cosa— pero romperla genera APIs confusas e inconsistentes con el resto del ecosistema.

Operación CRUDMétodo HTTPPropósito
CreatePOSTCrear un nuevo recurso (ej: agregar un producto nuevo).
ReadGETLeer uno o varios recursos existentes, sin modificarlos.
UpdatePUTActualizar por completo un recurso existente.
DeleteDELETEEliminar un recurso existente.
💡
Analogía práctica: Pensá en un fichero de biblioteca: POST es agregar una ficha nueva, GET es consultar una o varias fichas sin tocarlas, PUT es reescribir una ficha existente, y DELETE es sacarla del fichero. Es exactamente la misma lógica que aplicamos sobre los productos de la tienda virtual.

02Preparando un Recurso en Memoria

Antes de conectar una base de datos real (Bloque 6), vamos a simular el almacenamiento de datos con un simple array en memoria. No persiste entre reinicios del servidor, pero permite entender el CRUD completo sin la complejidad adicional de SQL todavía.

javascript
let productos = [
  { id: 1, nombre: 'Mouse inalambrico', precio: 4500 },
  { id: 2, nombre: 'Teclado mecanico', precio: 12000 },
];

Este array va a vivir, por ahora, en el mismo archivo donde definimos las rutas. Más adelante en esta misma clase lo vamos a mover a un lugar más ordenado dentro de la estructura del proyecto.

03Implementando Create (POST) y Read (GET)

El Read normalmente se divide en dos variantes: obtener todos los recursos, u obtener uno solo por su identificador. El Create recibe los datos del nuevo recurso en el req.body y los agrega a la colección.

javascript
// READ: todos los productos
app.get('/productos', (req, res) => {
  res.json(productos);
});

// READ: un producto puntual por id
app.get('/productos/:id', (req, res) => {
  const producto = productos.find(p => p.id === Number(req.params.id));
  if (!producto) return res.status(404).json({ error: 'No encontrado' });
  res.json(producto);
});

// CREATE: nuevo producto
app.post('/productos', (req, res) => {
  const nuevo = { id: productos.length + 1, ...req.body };
  productos.push(nuevo);
  res.status(201).json(nuevo);
});
⚠️
Sobre el status 201: Cuando una operación POST crea un recurso exitosamente, la convención REST indica devolver el código 201 (Created), no el 200 genérico. Es una señal explícita para quien consume la API de que algo nuevo fue efectivamente persistido.

04Implementando Update (PUT) y Delete (DELETE)

El Update localiza el recurso por su identificador y reemplaza sus datos con los nuevos valores recibidos. El Delete localiza el recurso y lo remueve de la colección.

javascript
// UPDATE: reemplazar un producto existente
app.put('/productos/:id', (req, res) => {
  const index = productos.findIndex(p => p.id === Number(req.params.id));
  if (index === -1) return res.status(404).json({ error: 'No encontrado' });
  productos[index] = { ...productos[index], ...req.body };
  res.json(productos[index]);
});

// DELETE: eliminar un producto
app.delete('/productos/:id', (req, res) => {
  const index = productos.findIndex(p => p.id === Number(req.params.id));
  if (index === -1) return res.status(404).json({ error: 'No encontrado' });
  productos.splice(index, 1);
  res.sendStatus(204);
});
🛡️
Sobre el status 204: 204 (No Content) indica éxito sin cuerpo de respuesta. Es la convención habitual para un DELETE exitoso: no hace falta devolver nada porque el recurso ya no existe.

05El Problema del Archivo Único

El archivo index.js con las cuatro rutas anteriores ya ronda las 30 líneas solo para un recurso. En un proyecto real la tienda virtual va a tener productos, usuarios, pedidos, categorías: si todo convive en un único archivo, se vuelve imposible de mantener y de revisar en equipo.

La estructura routes/ y controllers/ que dejamos preparada en la Clase 21 existe exactamente para resolver este problema: separar qué URL responde a qué (rutas) de qué hace realmente cada operación (controllers).

06Organizando con express.Router()

Express provee express.Router(), un mini-objeto de aplicación que permite agrupar rutas relacionadas en su propio archivo, y luego "montarlas" en la aplicación principal con un prefijo común.

javascript
// routes/productos.routes.js
const express = require('express');
const router = express.Router();
const controller = require('../controllers/productos.controller');

router.get('/', controller.obtenerTodos);
router.get('/:id', controller.obtenerPorId);
router.post('/', controller.crear);
router.put('/:id', controller.actualizar);
router.delete('/:id', controller.eliminar);

module.exports = router;
javascript
// controllers/productos.controller.js
let productos = [
  { id: 1, nombre: 'Mouse inalambrico', precio: 4500 },
];

exports.obtenerTodos = (req, res) => res.json(productos);

exports.obtenerPorId = (req, res) => {
  const producto = productos.find(p => p.id === Number(req.params.id));
  if (!producto) return res.status(404).json({ error: 'No encontrado' });
  res.json(producto);
};

exports.crear = (req, res) => {
  const nuevo = { id: productos.length + 1, ...req.body };
  productos.push(nuevo);
  res.status(201).json(nuevo);
};

Finalmente, en index.js, la ruta se "monta" con un prefijo:

javascript
// index.js
const productosRoutes = require('./routes/productos.routes');

app.use(express.json());
app.use('/productos', productosRoutes);

app.listen(3000, () => console.log('Servidor arriba'));
💡
Cómo leer app.use('/productos', productosRoutes): Todo lo que esté declarado dentro de productosRoutes con router.get('/') en realidad va a responder en /productos, y router.get('/:id') va a responder en /productos/:id. El prefijo se \u00ababsorbe\u00bb automáticamente al montar el router.
