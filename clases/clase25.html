Introducción a Bases de Datos

Descubrí por qué una base de datos reemplaza a los arrays en memoria, entendé la diferencia entre SQL y NoSQL, y dominá los conceptos de tablas, tipos de dato y claves antes de escribir la primera línea de SQL.

60 minutos Requiere Clase 24
Objetivos de la clase
  • Entender qué es una base de datos y por qué reemplaza a los arrays en memoria que usamos hasta ahora.
  • Distinguir las bases de datos SQL (relacionales) de las bases de datos NoSQL.
  • Comprender el modelo relacional: tablas, filas y columnas.
  • Conocer los tipos de datos básicos disponibles en PostgreSQL.
  • Entender qué es una clave primaria y qué es una clave foránea, y para qué sirve cada una.
  • Identificar cómo se relacionan dos tablas entre sí en un caso simple de uno a muchos.
  • Instalar PostgreSQL, Antares SQL Client y Postman, dejando el entorno de trabajo completo.

01¿Qué es una Base de Datos?

Hasta ahora, en el Bloque 5, guardamos los productos de la tienda virtual en un simple array de JavaScript, viviendo en la memoria RAM del proceso de Node.js. Esto funciona para aprender, pero tiene un problema grave: en el momento en que el servidor se reinicia (algo que sucede todo el tiempo, incluso sin querer), todos los datos se pierden. Además, ese array solo existe dentro de un único proceso, así que no hay forma de compartirlo entre distintos servidores o distintas instancias de la aplicación.

Una base de datos es un sistema especializado, separado de la aplicación, diseñado específicamente para guardar información de forma persistente (sobrevive a los reinicios), ordenada y consultable de manera eficiente, incluso cuando hay millones de registros.

💡
Analogía práctica: El array en memoria es como escribir notas en una pizarra: rápido y práctico, pero se borra apenas se apaga la luz. Una base de datos es como un archivo físico bien organizado: más lento de escribir a mano, pero la información queda guardada de forma confiable y se puede consultar cualquier día.

02SQL vs NoSQL: Dos Paradigmas de Almacenamiento

Existen dos grandes familias de bases de datos. Las SQL (también llamadas relacionales) organizan la información en tablas con una estructura fija y predecible, muy similares a una hoja de cálculo. Las NoSQL son más flexibles y guardan la información en formatos variados, como documentos tipo JSON, sin exigir una estructura rígida previa.

AspectoSQL (Relacional)NoSQL
EstructuraTablas con columnas fijas y tipos de dato definidos.Documentos, pares clave-valor, u otros formatos flexibles.
EjemplosPostgreSQL, MySQL, SQL Server.MongoDB, Firebase, Redis.
Cuándo convieneDatos con relaciones claras entre sí (usuarios, pedidos, productos).Datos muy variables entre registros, o que cambian de forma seguido.
🛡️
Por qué elegimos PostgreSQL: Para la tienda virtual —con productos, usuarios y pedidos claramente relacionados entre sí— el modelo relacional encaja naturalmente. Además, PostgreSQL es gratuito, de código abierto, y uno de los motores SQL más usados en el mundo profesional.

03El Modelo Relacional: Tablas, Filas y Columnas

En una base de datos relacional, la información se organiza en tablas. Cada tabla representa un tipo de entidad concreta (por ejemplo, productos). Dentro de la tabla, cada fila (también llamada registro) es una instancia particular de esa entidad, y cada columna es un atributo o característica que todas las filas comparten.

idnombreprecio
1Mouse inalambrico4500
2Teclado mecanico12000

En este ejemplo, productos es la tabla, cada fila es un producto puntual, y id, nombre y precio son las columnas que definen qué información guarda cada producto.

04Tipos de Datos Básicos en PostgreSQL

A diferencia de JavaScript, donde una variable puede cambiar de tipo libremente, en una tabla SQL cada columna tiene un tipo de dato fijo, declarado al momento de crear la tabla. Esto obliga a que todos los valores de esa columna sean consistentes entre sí.

Tipo en PostgreSQLQué guarda
INTEGERNúmeros enteros, sin decimales (ej: cantidad de stock).
VARCHAR(n)Texto corto, con un largo máximo de n caracteres (ej: nombre de producto).
TEXTTexto largo, sin límite práctico de longitud (ej: descripción de producto).
NUMERIC(p,s)Números decimales exactos, ideales para precios y montos de dinero.
BOOLEANVerdadero o falso (ej: si un producto está activo o no).
DATEUna fecha, sin componente de hora (ej: fecha de alta de un producto).
⚠️
Sobre NUMERIC para precios: Nunca se usa un tipo de punto flotante (como FLOAT) para representar dinero, porque puede introducir pequeños errores de redondeo. NUMERIC(10,2) es la elección estándar para precios: hasta 10 dígitos en total, con 2 decimales exactos.

05Claves Primarias y Claves Foráneas

La clave primaria (Primary Key) es la columna (o combinación de columnas) que identifica de forma única e inequívoca a cada fila de una tabla. No puede repetirse entre filas, y no puede quedar vacía. En casi todas las tablas, se usa una columna id numérica que se autoincrementa con cada fila nueva.

La clave foránea (Foreign Key) es una columna que guarda el id de una fila perteneciente a otra tabla, estableciendo así una relación entre ambas. Es el mecanismo central que le da sentido a la palabra "relacional".

Tabla pedidosDescripción
idClave primaria de la tabla pedidos.
producto_idClave foránea: apunta al id de una fila en la tabla productos.
cantidadCuántas unidades de ese producto se pidieron.
💡
Analogía práctica: Pensá en el DNI de una persona como su clave primaria: identifica a una única persona sin ambigüedad. Si un formulario de otra oficina pide \u00abnúmero de DNI del titular\u00bb, ese campo es una clave foránea: no describe a la persona en sí, apunta a quién es realmente consultando el registro original.

06Relaciones entre Tablas: Uno a Muchos

La relación más común y sencilla entre dos tablas es la de uno a muchos: una fila de una tabla puede estar asociada a varias filas de otra tabla, pero cada una de esas filas asociadas solo pertenece a una única fila de la primera.

En la tienda virtual, un ejemplo claro es la relación entre productos y categorías: una categoría puede tener muchos productos, pero cada producto pertenece a una sola categoría. Esto se modela agregando una columna categoria_id (clave foránea) en la tabla de productos, que apunta al id de la tabla de categorías.

🛡️
Por qué importa entender esto ahora: Este mismo patrón de uno a muchos es el que vamos a usar en la Clase 27 con JOIN, para combinar datos de varias tablas relacionadas en una sola consulta.

07Instalando el Entorno: PostgreSQL, Antares y Postman

Para practicar SQL de forma real (no solo conceptual), hace falta instalar tres herramientas: el motor de PostgreSQL, un gestor visual de bases de datos, y Postman para probar la API más adelante. Esta sección es una guía paso a paso completa para dejar todo instalado.

HerramientaPara qué se usa
PostgreSQLEl motor de base de datos en sí: el programa que efectivamente guarda y procesa los datos.
Antares SQL ClientGestor visual multiplataforma para crear bases de datos, tablas, y ejecutar consultas SQL sin escribir todo a mano.
PostmanHerramienta para probar los endpoints de la API que vamos a construir en el Bloque 5 y en el Proyecto Final.

Instalando PostgreSQL en Windows

Descargar el instalador oficial desde postgresql.org/download/windows, ejecutarlo, y avanzar con las opciones por defecto. Durante la instalación se pide definir una contraseña para el usuario administrador postgres: anotarla, porque se va a usar todo el curso. El puerto por defecto es 5432; se deja tal cual. Al finalizar, se puede omitir la instalación de Stack Builder (herramientas adicionales que no vamos a necesitar).

Instalando PostgreSQL en macOS

La forma más simple es descargar Postgres.app desde postgresapp.com, arrastrarlo a la carpeta Aplicaciones, y abrirlo. Al iniciarlo por primera vez, un botón "Initialize" crea el servidor automáticamente, ya escuchando en el puerto 5432, con el usuario postgres sin contraseña por defecto (se puede definir una desde Antares más adelante).

Instalando PostgreSQL en Linux (Ubuntu/Debian)

bash
sudo apt update
sudo apt install postgresql postgresql-contrib
sudo systemctl start postgresql
sudo systemctl enable postgresql

# Definir contrasena para el usuario postgres
sudo -u postgres psql -c "ALTER USER postgres PASSWORD 'tu_contrasena';"

Instalando Antares SQL Client

Antares es un gestor visual de bases de datos gratuito y multiplataforma (Windows, macOS, Linux), similar en propósito a pgAdmin pero con una interfaz más liviana y moderna. Se descarga desde antares-sql.app, eligiendo el instalador correspondiente al sistema operativo, y se instala como cualquier otra aplicación de escritorio.

Una vez instalado y abierto, se crea una nueva conexión hacia el servidor de PostgreSQL recién instalado:

Campo de conexiónValor
ClientPostgreSQL
Hostlocalhost
Puerto5432
Usuariopostgres
ContraseñaLa definida durante la instalación de PostgreSQL

Al confirmar la conexión, Antares muestra en el panel izquierdo todas las bases de datos existentes en el servidor, y permite crear bases de datos, tablas y ejecutar consultas SQL desde un editor visual, exactamente igual a lo que se venía haciendo antes con pgAdmin.

🛡️
Por qué Antares en este curso: Antares ofrece una experiencia más simple para quien recién arranca con SQL, con un editor de consultas más directo y una interfaz más moderna que pgAdmin, sin perder ninguna funcionalidad necesaria para el curso.

Instalando y Configurando Postman

Postman ya se había instalado al comienzo del curso, pero conviene volver a verificar la instalación y repasar su configuración antes de arrancar con SQL y, más adelante, con la conexión real entre Node.js y PostgreSQL.

Se descarga desde postman.com/downloads, eligiendo la versión de escritorio correspondiente al sistema operativo. Al abrirlo por primera vez, se puede crear una cuenta gratuita o continuar sin cuenta ("Skip and go to the app"); para este curso no es indispensable tener cuenta.

La configuración recomendada para el resto del curso:

PasoQué hacer
1Crear un nuevo Workspace (o usar el que viene por defecto) llamado, por ejemplo, "Backend desde Cero".
2Dentro del workspace, crear una Collection nueva llamada "Tienda Virtual API", donde se van a ir guardando todos los requests de prueba de las próximas clases.
3Crear una Environment (entorno) con una variable llamada baseUrl, apuntando por ahora a http://localhost:3000. Esto va a permitir cambiar entre local y producción sin reescribir cada request.
4Verificar que la Collection tenga guardado el header Content-Type: application/json para los requests que envíen body.
💡
Por qué usar variables de entorno en Postman: Cuando en la Clase 32 la API se despliegue en internet, alcanza con cambiar el valor de baseUrl en el Environment, sin tener que editar uno por uno todos los requests guardados en la Collection.
