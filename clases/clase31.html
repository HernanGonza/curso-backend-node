Proyecto Final: Validaciones y Manejo de Errores

Agregamos un middleware de validación para los datos de entrada y centralizamos el manejo de errores con un middleware dedicado, dejando la API robusta ante datos incorrectos.

60 minutos Requiere Clase 30
Objetivos de la clase
  • Entender qué significa validar datos de entrada y por qué es necesario hacerlo en el servidor.
  • Escribir un middleware de validación reutilizable para el recurso productos.
  • Aplicar el middleware únicamente a las rutas que reciben body: POST y PUT.
  • Centralizar el manejo de errores con un middleware dedicado de cuatro parámetros.
  • Distinguir errores de datos inválidos (400), recurso no encontrado (404) y error interno (500).

01Por Qué Validar los Datos de Entrada

Hasta la Clase 30, la API confía ciegamente en que el body de un POST o PUT viene completo y bien formado. Validar significa revisar esos datos antes de que lleguen a la base de datos, y responder con un error claro si algo no está bien.

🛡️
Por qué no confiar en el frontend: Un request se puede armar manualmente con Postman o código, sin pasar por ningún formulario. La única validación que protege la base de datos es la que corre en el servidor.

02Middleware de Validación: validarProducto

Un middleware de Express se ejecuta antes del controller, con acceso a req, res y next. Si todo está bien llama a next(); si algo falla, responde directamente.

javascript
// middlewares/validarProducto.js
function validarProducto(req, res, next) {
  const { nombre, precio, categoria_producto_id } = req.body;

  if (!nombre || typeof nombre !== 'string' || nombre.trim() === '') {
    return res.status(400).json({ error: 'El campo nombre es obligatorio y debe ser texto' });
  }
  if (precio === undefined || typeof precio !== 'number' || precio <= 0) {
    return res.status(400).json({ error: 'El campo precio es obligatorio y debe ser un numero mayor a 0' });
  }
  if (!categoria_producto_id || typeof categoria_producto_id !== 'number') {
    return res.status(400).json({ error: 'El campo categoria_producto_id es obligatorio y debe ser numerico' });
  }

  next(); // Todo esta en orden: dejamos pasar el request
}

module.exports = validarProducto;
💡
Por qué status 400: Es la convención estándar cuando el problema está en los datos enviados por el cliente.

03Aplicando el Middleware a las Rutas

javascript
// routes/productos.routes.js (actualizado)
const express = require('express');
const router = express.Router();
const controller = require('../controllers/productos.controller');
const validarProducto = require('../middlewares/validarProducto');

router.get('/', controller.obtenerTodos);
router.get('/:id', controller.obtenerPorId);
router.post('/', validarProducto, controller.crear);
router.put('/:id', validarProducto, controller.actualizar);
router.delete('/:id', controller.eliminar);

module.exports = router;
⚠️
Por qué no en GET y DELETE: Esas rutas no reciben body con datos del producto.

04Manejo Centralizado de Errores

Un middleware de manejo de errores recibe cuatro parámetros: (err, req, res, next). Express lo detecta automáticamente por esa firma.

javascript
// middlewares/errorHandler.js
function errorHandler(err, req, res, next) {
  console.error(err.stack);

  // Codigo de error de PostgreSQL cuando una clave foranea no existe
  if (err.code === '23503') {
    return res.status(400).json({ error: 'La categoria_producto_id enviada no existe' });
  }

  res.status(500).json({ error: 'Error interno del servidor' });
}

module.exports = errorHandler;
🛡️
Sobre el código 23503: Es el código estándar de PostgreSQL para violaciones de clave foránea.

05Conectando el errorHandler en index.js

javascript
// index.js (actualizado)
require('dotenv').config();
const express = require('express');
const productosRoutes = require('./routes/productos.routes');
const errorHandler = require('./middlewares/errorHandler');

const app = express();
app.use(express.json());
app.use('/productos', productosRoutes);

app.use(errorHandler); // Siempre al final

const PORT = process.env.PORT || 3000;
app.listen(PORT, () => {
  console.log(`Servidor corriendo en el puerto ${PORT}`);
});
